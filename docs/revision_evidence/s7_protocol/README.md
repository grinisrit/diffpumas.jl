# S7 protocol run: archived text outputs

Output of the pre-registered S7 reconstruction protocol (MLEM vs Gauss-Newton; fields D and T; arms X, Mc, M)
from branch `s7-protocol`, code commit `21b8670` (analysis scripts added in `8552f8c`).
Run 2026-11-12 21:38Z to 2026-11-14 13:02Z (`RUN_START`, `RUN_DONE`), 34 single-thread worker processes,
cuts 0-4 applied (`cuts.toml`; the 36 h limit was not met, `limit_met = false` in `selection.toml`),
template mode `replicates`. Only small text artifacts are archived.

## Files

- `selection.toml`, `selection.toml.sha256`: frozen development-stage selection used by the test stage (content hash 6fc0a948...).
- `cuts.toml`: the cuts applied to fit the time limit, with the projected hours per cut.
- `dry_calibration.toml`, `.sha256`: dry calibration constants (dry scale 0.9022) used by arm Mc.
- `dry_calibration_shared_seed44.toml`, `.sha256`: variant of the dry calibration with a shared seed (record of an earlier gate attempt).
- `test_summary.tsv`: test-stage cell statistics and contrasts (mean, sd, interval per arm, solver, exposure).
- `test/rows_shard*.tsv`: per-solve rows of the test stage (field T); `test/manifest_*.toml`: per-worker manifests.
- `dev/rows_phase*_shard*.tsv`, `dev/sel_phase*.toml`, `dev/grids.toml`, `dev/manifest_*.toml`: development stage rows, per-phase selections, grids, manifests.
- `diag/rows_shard*.tsv`, `diag/manifest_*.toml`: oracle-weight diagnostic (GN-0, arm Mc, tau 1e4 and 1e8).
- `gate/cells.tsv`, `gate/g1.toml`: G1 gate report (truth only) and crossed-cell list.
- `g0c/`: gate G0c (sweep vs validation driver on the same dry rays): `g0c_verdict.toml`, `sweep_rock.toml`, `sweep_values.tsv`, `validation_values.csv`.
- `dry/dry_report.toml`: dry calibration checks.
- `dry*.log`, `g0c_*.log`, `gate_run.log`, `timing_t2.log`: gate, dry and timing logs.
- `log_templates.txt`, `log_dev.txt`, `log_test.txt`, `log_diag.txt`, `log_summary.txt`: one log per stage.
- `resources.log`: resource monitor samples.
- `RUN_START`, `RUN_DONE`, `RUN_STATUS`, `TEMPLATE_MODE`, `WORKERS_WANTED`: run markers and status.

The `*.log` files are matched by a global ignore rule and are force-added.

## Not archived

`templates/` (MC and exact templates, `.jls`, 5 MB), `recs/` directories (saved reconstructions, `.jls`, about 40 MB),
the `claims/` lock directories, `g0c/sweep_rays.jls`, and `orch.out`. They are regenerated by the same scripts.

## Regeneration

    OUT=/path/to/out NPROC=34 examples/s7_protocol.sh run

runs templates, dev, test, diag and summary in order (steps can be run singly: `gate`, `g0c`, `dry`, `templates`, `dev`,
`test`, `diag`, `summary`); `examples/s7_monitor.sh` adjusts the worker count. Every solve is fixed by its seed, so results
do not depend on scheduling. Templates are rebuilt by the `templates` step, reconstructions by the `test` step.
Post-run analysis and the paper figures `fig_s7_sweep`, `fig_s7_field`: see `dev/s7_analysis/README.md`
(`make_s7_figure.py [OUT [FIGDIR [FACTS]]]`, needs `test/recs`, hence a re-run or the original output directory).
Tests: `julia --project=. -t 1 test/test_s7_protocol.jl`.
