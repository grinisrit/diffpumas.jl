# Getting Started

This guide gets you from a fresh checkout to a working physics-table lookup and
a first muon flux calculation.

## Requirements

DiffPumas.jl targets Julia 1.10 or newer. The project environment is declared in
`Project.toml` and includes dependencies such as Zygote, ChainRulesCore,
PlotlyJS, TetGen, StaticArrays, and ArgParse. Ray/triangle intersection is
bundled as `DiffPumas.TriangleIntersect`; no unregistered package or local
`Pkg.develop` step is required. `Manifest.toml` is intentionally ignored, so
`Pkg.instantiate()` resolves the compatible versions declared in `Project.toml`.

From the repository root:

```bash
julia --project=. -e 'using Pkg; Pkg.instantiate()'
```

Use the same project environment for tests and examples:

```bash
julia --project=.
julia --project=. examples/loader_example.jl --help
julia --project=. -e 'using Pkg; Pkg.test()'
```

The recorded full-suite verification on 2026-10-23 passed 557 tests on Julia
1.10.12 with Zygote 0.7.13
and Julia 1.11.7 with Zygote 0.7.10. The 1.10 environment was resolved from
`Project.toml` without the local manifest. The loader example was also checked
on Julia 1.11.7 with Zygote 0.7.10,
using both the empirical fallback and upstream muon tables at dataset commit
`d00fd31e5365b699b2d077232313f0c36343a837` (StandardRock, Water, Air).
The CI matrix is configured to resolve a fresh environment on Julia 1.10 and
1.11; it uses
empirical tables so external datasets are not required for the installation check.

## Load the Package

Start a Julia REPL in the project:

```bash
julia --project=.
```

Then load DiffPumas:

```julia
using DiffPumas

println(version())
pumas_info()
```

`pumas_info()` prints a short summary of supported particles and transport
modes.

## Optional PUMAS stopping-power data

A fresh checkout runs without external data: `create_physics` warns and uses
its empirical formulas when a material table is absent. Those approximations
are useful for smoke tests, but are not interchangeable with the precise PUMAS
tables when reproducing physical results. Physics dumps cache the chosen tables;
remove an old dump or select a new dump filename after changing the data source.

For the PUMAS tables, download the upstream
[niess/pumas-materials](https://github.com/niess/pumas-materials) dataset, then
set its root explicitly before starting Julia:

```bash
git clone https://github.com/niess/pumas-materials.git /path/to/pumas-materials
git -C /path/to/pumas-materials rev-parse HEAD
export PUMAS_MATERIALS_PATH=/path/to/pumas-materials
test -f "$PUMAS_MATERIALS_PATH/dedx/muon/standard_rock.txt"
julia --project=. examples/loader_example.jl --dump examples/data/materials.pumas
```

Record the printed dataset commit alongside results. The upstream README says
these stopping-power files were generated by PUMAS, and provides LGPLv3 license
terms. DiffPumas reads them; it does not generate or download them automatically.
The `dedx/muon` and `dedx/tau` directories select the particle. An explicit
`PhysicsSettings(dedx_path="/path/to/pumas-materials")` also selects a dataset.
The environment variable takes precedence over the legacy sibling directory
`../pumas-materials`. Check the `Loaded PUMAS tables` messages to verify which
files were actually used.

## Pinned Revision Physics Dump

The revision records the three upstream muon tables at commit
`d00fd31e5365b699b2d077232313f0c36343a837` under
`examples/data/revision_physics/pumas-materials/`, together with upstream
license files. Its `materials.xml` is a byte-for-byte copy of the example MDF.
`INPUT_SHA256SUMS` verifies those inputs. `provenance.json`, `loader.log`, and
`SHA256SUMS` record the initial generation, including the generated dump hash.
The historical `examples/data/materials.pumas` is left unchanged.

Rebuild from the pinned inputs after package installation:

```bash
bash dev/create_revision_physics.sh
# To compare a fresh rebuild without replacing existing evidence:
bash dev/create_revision_physics.sh /path/to/new-physics-output
bash dev/run_lvd_paper.sh --dump /path/to/new-physics-output/materials.pumas --dry-run
```

The creation script verifies input hashes, uses the recorded MDF and material
tables, and refuses to replace an existing dump. A rebuild records its Julia
version, command, loader output, and output hashes. Julia serialization can vary
across versions; record the generated hash for the actual computation, rather
than expecting byte-identical dumps across Julia versions. The paper launcher
passes its selected dump to every tomography stage.

## Create Physics Tables In Memory

For quick checks, create tables directly:

```julia
using DiffPumas

physics = create_physics(MUON; n_energies = 80, K_min = 1e-2, K_max = 1e6)

rock_idx = get_material_index(physics, "StandardRock")
air_idx = get_material_index(physics, "Air")

@show rock_idx air_idx
@show property_range(physics, ENERGY_LOSS_CSDA, rock_idx, 10.0)
@show property_stopping_power(physics, ENERGY_LOSS_CSDA, rock_idx, 10.0)
```

Use direct creation in tests or small notebooks. For repeated example runs, use
the dump workflow below so physics table construction is cached.

## Create or Reuse a Physics Dump

Most examples use `examples/data/materials.xml` and cache tables in a `.pumas`
dump:

```bash
julia --project=. examples/loader_example.jl \
  --mdf examples/data/materials.xml \
  --dump examples/data/materials.pumas \
  --particle muon
```

The loader prints available material names and sample CSDA ranges. Subsequent
examples can reuse the dump:

```bash
julia --project=. examples/diff_flux.jl \
  --dump examples/data/materials.pumas \
  --thickness 100 \
  --density 2650 \
  --zenith-max 45 \
  --samples 100
```

If the dump is missing, scripts that call `DiffPumas.Pumas.load_or_create_physics`
will usually rebuild it from the MDF path they provide.

## First Flux Calculation

The high-level two-layer geometry is rock below an exponential atmosphere. The
detector sits at `z = 0`, rock extends upward to `rock_thickness`, and the
primary-flux surface is above that.

```julia
using DiffPumas

physics = create_physics(MUON; n_energies = 80, K_min = 1e-2, K_max = 1e6)

flux, sigma = compute_flux(
    physics,
    2650.0,  # rock density, kg/m^3
    100.0,   # rock thickness, m
    45.0,    # elevation angle, degrees
    1e-3,    # detector energy min, GeV
    1e6;     # detector energy max, GeV
    n_samples = 100,
    seed = 42,
    straggling = true,
    scattering = true,
    energy_threshold_low = 100.0,
)

println("flux = $flux +/- $sigma")
```

For a deterministic AD-friendly CSDA value at one final energy:

```julia
using DiffPumas

physics = create_physics(MUON; n_energies = 80, K_min = 1e-2, K_max = 1e6)

flux = compute_flux_differentiable_csda(
    physics,
    2650.0,  # density, kg/m^3
    100.0,   # thickness, m
    45.0,    # elevation, degrees
    10.0,    # final kinetic energy, GeV
    1.0,     # charge
)

println(flux)
```

## First Density Gradient

The direct CSDA path is the most convenient route for a density sensitivity:

```julia
using DiffPumas

physics = create_physics(MUON; n_energies = 80, K_min = 1e-2, K_max = 1e6)

flux, dflux_drho = compute_flux_gradient_csda(
    physics,
    2650.0,  # density, kg/m^3
    100.0,   # thickness, m
    45.0,    # elevation, degrees
    10.0,    # final kinetic energy, GeV
    1.0,     # charge
)

println("flux = $flux")
println("dflux/drho = $dflux_drho")
```

For an integrated flux over sampled energies, see `examples/diff_flux.jl`, which
pre-samples random values before differentiating so the AD target is
deterministic.

## Common Problems

If `using DiffPumas` fails, instantiate the environment:

```bash
julia --project=. -e 'using Pkg; Pkg.instantiate()'
```

If an example cannot find `StandardRock`, `Air`, or `Water`, rebuild the dump
from `examples/data/materials.xml` with `examples/loader_example.jl`.

If a stochastic example is slow, lower `--samples`, `--n-angles`,
`--mc-samples`, or run only a script part with `--part`. Low-statistics runs are
for smoke tests and API checks; they are not physics-quality results.

If a Zygote gradient is unexpectedly `nothing` or very slow, make sure the code
path is deterministic and avoids random sampling inside the differentiated
function. Prefer direct CSDA helpers for gradients.
